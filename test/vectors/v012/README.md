# v0.12 vectors

- `upstream-invoices.json`: extracted by `scripts/extract-vectors.py` from the tests in `sonic-callreq` 0.12.0 `src/uri.rs` (Apache-2.0, AluVM / RGB-WG).
- `DemoToken.rgb`: a contract consignment from the pinned `rgb-wallet` 0.12.0-rc.3, made offline from the RGB-WG/rgb v0.12.0-rc.3 `examples/` folder: `rgb -d data init`, `rgb -d data import RGB20-FNA.issuer`, `rgb -d data issue -w alice DemoToken.yaml`, `rgb -d data backup -f DemoToken DemoToken.rgb`. The pinned binary's `rgb -d data2 accept -w bob -u DemoToken.rgb` accepts it. The contract ID is `contract:nztjpjRX-_NVDDgd-EHENsqL-AKsGsyV-F6LzljB-X4WTv0Y`, the same one the RGB Docs quick-start shows.

The trusted issuer `rust/v012/issuers/RGB20-FNA.issuer` is copied from RGB-WG/rgb v0.12.0-rc.3 `examples/` (Apache-2.0).

- `TransferDemo.transfer.rgb`: a transfer consignment made by `rust/gen-v012` (see its `src/main.rs`) with `rgb-runtime` 0.12.0-rc.3, without any indexer or network. It starts from a fresh copy of the examples `data/`, plus `rgb -d data import RGB20-FNA.issuer` and Bob's auth token from `rgb -d data2 invoice -w bob --nonce 0 --seal-only DemoToken`. The generator gives Alice's demo wallet a made-up funding transaction (`b6bd8fa3…479b:0`, never broadcast), issues DemoToken on it as `TransferDemo` (`contract:KA73QdAH-BFBUNYX-0jsaAXq-_wKsXwD-2VLkZ9Q-1yRYYkc`), and pays Bob 10 with `pay_invoice`. The witness `fb0edb5f…49fc` is unsigned, which client-side validation doesn't need. The pinned `rgb-wallet` 0.12.0-rc.3 accepts it: `rgb -d <copy of data2> accept -w bob -u TransferDemo.transfer.rgb` exits 0, and the same file with byte 5000 flipped is rejected.
